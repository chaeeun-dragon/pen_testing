# 해온카드 공격 시나리오 촬영 대본 v1.0

대상: `HAEON-DIAG-01` 해온카드 가맹점 결제 연동 진단 API 침해 시나리오

촬영 방식: 해온카드 홈 → 공격 콘솔 → 가맹점 로그인·정상 진단 → 공격 콘솔 Before·대응·After → 회원 마이페이지
예상 분량: 본편 약 6~8분. 실행·화면 전환 시간은 별도.

이 영상은 **해온카드 자체 시나리오**를 보여 준다. 화면에 북웨이브와 PG 메뉴가 보여도 이번 시연에서는 선택하지 않는다. 가맹점 페이지의 `결제 연동 점검`은 결제 승인 화면이 아니라 등록된 대상의 연결 상태를 확인하는 정상 업무다.

## 촬영 전 준비 — 녹화 전

1. WSL에서 프로젝트 루트로 이동해 `docker compose --env-file .env up -d --build haeon-lab-gateway`를 실행한다. `docker compose --env-file .env ps`에서 게이트웨이와 의존 서비스가 healthy인지 확인한다.
2. 브라우저 탭 네 개를 준비한다. 주소가 열리지 않으면 먼저 서비스 상태를 확인한다.

   | 탭 | 주소 | 용도 |
   |---|---|---|
   | 해온카드 홈 | `http://127.0.0.1:8090/` | 카드사 소개와 가맹점 진입점 |
   | 공격 콘솔 | `http://127.0.0.1:8094/` | 정상·Before·대응·After 실행과 증거 |
   | 가맹점 페이지 | `http://127.0.0.1:8090/merchant/` | 로그인과 정상 연결 진단 |
   | 회원 마이페이지 | `http://127.0.0.1:8090/mypage` | 영향 회원 보호 안내 |

   `haeon.localhost:8090`과 `haeon-attack.localhost:8090`도 게이트웨이 주소지만, 촬영 환경에서 이름이 해석되지 않을 수 있다. 위 `127.0.0.1` 주소는 2026-09-23에 HTTP 200을 확인했다.

3. 가맹점·회원 계정의 로그인은 준비하되 비밀번호 입력 장면은 녹화하지 않는다. 로그인 전후만 컷으로 연결한다. 화면에는 세션 토큰이나 `attack-response.json` 원문을 띄우지 않는다.
4. 공격 콘솔에 이전 Before 실행이 `대응 대기`로 남아 있으면 해당 실행의 `대응 실행`을 먼저 완료한다. 새 촬영은 정상 기준선에서 시작한다. 기존 실행 기록이 콘솔에 보여도 새 실행 ID를 기준으로 설명한다.
5. 창 전환이 많으면 브라우저 탭 제목을 `① 해온 홈`, `② 공격 콘솔`, `③ 가맹점`, `④ 회원 MY` 순서로 정하고, 녹화 영역에서 주소창·알림·개인 계정 정보를 가린다.

## 본편 대본

### 01. 해온카드 메인 화면 — 도입

- **화면·조작:** 해온카드 홈을 전체 화면으로 열고 상단 `가맹점` 메뉴를 가리킨다. 아직 클릭하지 않는다.
- **확인:** 카드사 로고와 메인 화면, 가맹점 진입 메뉴.
- **발표 멘트:** “이번 시연의 대상은 해온카드입니다. 카드사 홈과 가맹점 지원 기능, 보안 운영 화면을 차례로 보겠습니다.”

### 02. 공격 콘솔 — 이번 실습 소개

- **화면·조작:** 공격 콘솔 탭으로 전환한다. 왼쪽 `해온카드 · 진단 API 침해`와 중앙 `공격 시나리오 제어`를 보여 준다.
- **확인:** `정상 진단`, `Before 공격 흐름`, `대응 실행`, `After 차단 검증` 네 카드.
- **발표 멘트:** “여기는 해온카드 실습 운영 콘솔입니다. 정상 동작을 먼저 확인한 뒤, 취약 상태의 결과와 운영자 대응, 개선된 상태를 같은 화면에서 비교합니다.”

### 03. 가맹점 페이지 — 로그인

- **화면·조작:** 해온카드 홈 탭으로 돌아가 상단 `가맹점`을 클릭한다. `가맹점 로그인` 화면을 2초 보여 준 뒤 비밀번호 입력 장면은 컷한다. 로그인 완료 화면으로 이어 붙인다.
- **확인:** 등록된 진단 대상, 점검 항목 `연결 상태 확인`, `가맹점 인증` 상태.
- **발표 멘트:** “가맹점은 해온카드에 로그인해 등록된 결제 연동 대상의 연결 상태를 점검할 수 있습니다. 결제를 일으키는 기능은 아닙니다.”

### 04. 가맹점 정상 진단 → 콘솔 기준선

- **화면·조작:** 가맹점 페이지에서 등록된 대상을 고르고 `연결 상태 확인`을 누른다. 결과의 `처리 상태`와 `응답 시간`을 잡는다. 공격 콘솔로 전환해 `정상 진단`을 한 번 실행한다.
- **확인:** 가맹점 페이지 `연결 상태 정상`; 공격 콘솔의 새 실행 ID와 정상 진단 완료.
- **발표 멘트:** “일반적인 연결 점검은 성공합니다. 이것이 공격 전 기준선이며, 이후에도 정상 업무는 계속 동작해야 합니다.”

### 05. 공격 콘솔 — 공격자 Before

- **화면·조작:** `Before 공격 흐름`을 누른다. 새 실행 ID를 화면에 잡고 `진행 요약`과 오른쪽 `보안 이벤트`를 천천히 훑는다. 화면의 단계 로그가 끝날 때까지 기다린다.
- **확인:** 제한된 모의 웹 세션 생성, 합성 결제 지원 자료 **20건 조회**, 내부 수신 결과, `ALERT`.
- **발표 멘트:** “공격자는 가맹점 진단 입력의 취약한 처리 경계를 노립니다. Before에서는 제한된 모의 웹 세션이 생기고 지정된 합성 자료 20건이 내부 수신기로 전송됩니다. 이 흔적을 보안 이벤트가 탐지합니다.”

### 06. 공격 콘솔 — 증거 확대

- **화면·조작:** 오른쪽 `상세 근거 로그`의 `보안 이벤트`와 `실행 로그`를 번갈아 보여 준다. 상단 `조회된 합성 자료`와 수신 결과를 짚는다.
- **확인:** 같은 실행 ID에 묶인 조회 건수·수신 상태·탐지 이벤트.
- **발표 멘트:** “이 결과는 해당 실행에서 남은 조회·전송·탐지 기록으로 확인합니다.”

### 07. 공격 콘솔 — 방어자 대응

- **화면·조작:** **같은 Before 실행**이 선택된 상태에서 `대응 실행`을 누른다. 버튼이 비활성이라면 `대응 대기 실행 열기`로 해당 실행을 먼저 선택한다.
- **확인:** 실행 상태 `대응 완료` 또는 `CONTAINED`, 모의 세션 폐기, 회원 보호 안내 등록.
- **발표 멘트:** “운영자는 탐지된 실행을 선택해 세션을 폐기합니다. 이때 영향 회원에게 추가 확인 안내도 등록합니다.”

### 08. 공격 콘솔 — After 재검증

- **화면·조작:** `After 차단 검증`을 누른다. 완료 후 `Before / After 결과 비교` 표를 한 화면에 담는다.
- **확인:** 비정상 입력 **HTTP 403**, `DIAGNOSTIC_INPUT_BLOCKED`; 세션·자료 조회·전송은 `선행 차단으로 미실행`.
- **발표 멘트:** “같은 비정상 입력을 개선된 경로에 다시 보냈습니다. 입력 단계에서 403으로 차단되어 세션도 만들지 않고, 자료 조회나 전송도 진행되지 않습니다.”

### 09. 회원 마이페이지 — 보호 안내

- **화면·조작:** 회원 마이페이지 탭으로 전환한다. 영향 회원으로 로그인한 화면에서 `보호 안내`의 `추가 확인이 필요합니다`를 보여 준다. `확인했습니다`를 누른 뒤 `확인 완료`로 바뀌는 장면을 잡는다.
- **확인:** 영향 회원의 안내·확인 시각. 필요하면 비교 회원으로 다시 로그인해 안내가 없는 상태를 짧게 보여 준다.
- **발표 멘트:** “방어 이후에는 영향 회원 본인에게만 보호 안내가 보입니다. 이 확인 버튼은 안내를 읽었다는 기록이며, 결제 중지나 사고 종료를 뜻하지 않습니다.”

### 10. 공격 콘솔 — 마무리

- **화면·조작:** 공격 콘솔로 돌아와 Before/After 비교 표와 최종 상태를 한 화면에 담는다.
- **확인:** Before의 자료 조회·내부 수신, 대응 완료, After 입력 차단.
- **발표 멘트:** “정상 진단은 유지하면서, 취약 경로에서는 합성 자료 접근과 전송 증거를 관측했고, 개선 경로에서는 같은 입력을 앞단에서 차단했습니다. 이것이 이번 해온카드 시나리오의 검증 결과입니다.”

### 장면 사이 연결 멘트

- 02 → 03: “먼저 공격 대상이 되는 정상 가맹점 기능을 보겠습니다.”
- 04 → 05: “이제 같은 진단 기능의 취약한 Before 경로를 실행합니다.”
- 06 → 07: “탐지에 그치지 않고 운영자가 이 실행에 대응합니다.”
- 08 → 09: “기술적 차단 이후 고객에게 보이는 안내까지 확인하겠습니다.”

## 운영 콘솔 대신 시연 터미널을 쓰는 촬영안

`http://127.0.0.1:8094/demo-terminal.html`은 같은 해온카드 시나리오를 촬영용 타이핑 화면으로 **새 실행**한다. 본편 장면 04~08을 아래 네 번의 버튼 조작으로 대체할 때 사용한다. 이미 운영 콘솔에서 Before를 실행했다면 그 실행의 대응을 끝낸 뒤 새 시연을 시작한다.

| 버튼 순서 | 자동 재생되는 내용 | 멈춰서 말할 한 문장 |
|---|---|---|
| `시연 시작 · 기준선 확인` | 환경 확인, 정상 진단 | “등록 대상의 정상 연결부터 확인했습니다.” |
| `다음 단계 · 공격자 Before` | Before 실행, 20건 조회·수신, 탐지 증거 | “공격자 흐름에서 제한 세션과 자료 전송 흔적이 남고 경보가 발생합니다.” |
| `다음 단계 · 방어자 대응 / After` | 세션 폐기·안내 등록, After 403 차단 | “운영자가 기존 실행을 차단하고, 개선 경로는 비정상 입력을 시작점에서 거절합니다.” |
| `다음 단계 · 회원 보호` | 회원 안내 장면으로 전환 | “마지막으로 회원 화면에서 실제 안내 상태를 확인합니다.” |

각 버튼의 타이핑과 상태 표시가 **끝난 후** 다음 버튼을 누른다. 터미널 오른쪽의 화면 카드는 대상 화면으로 가는 링크이며, 실제 회원 안내 확인은 마이페이지에서 직접 보여 준다. 시연 터미널과 운영 콘솔은 같은 실행을 이어받는 두 조작창이 아니므로 한 실행의 중간에서 제어 주체를 바꾸지 않는다.

## 촬영 중 헷갈리기 쉬운 판정

| 화면 결과 | 설명 |
|---|---|
| Before `ALERT` | 공격 흐름의 흔적이 탐지됐다는 뜻. 이 상태에서 운영자 대응을 이어 간다. |
| 대응 `CONTAINED` / `BLOCKED` | 해당 Before 실행의 제한 세션이 폐기되고 재사용이 거부된 상태. |
| After `403` | 비정상 진단 입력 자체가 차단됨. 후속 조회·전송은 **미실행**이다. |
| 내부 수신 20건 | 실제 외부 유출이 아니라 로컬 내부 수신기로 이동한 **합성 결제 지원 자료**다. |
| 회원 `확인 완료` | 보호 안내를 읽었다는 기록. 사고 복구나 결제 정지를 의미하지 않는다. |

화면의 “웹쉘”은 임의 OS 명령이나 실제 웹쉘 파일이 아니라 정해진 API 동작만 허용하는 제한 세션을 뜻한다. 북웨이브의 챗봇·랜섬웨어 시나리오와 북웨이브↔PG↔해온카드 결제 연동 시나리오는 이 촬영 대본에 포함하지 않는다.

## 촬영 종료

프로젝트 루트의 WSL에서 `bash tools/haeon-diagnostic-lab.sh reset`으로 현재 실습 상태와 보호 안내를 초기화한다. 저장된 `evidence/runs/` 증거는 유지된다. 재촬영 전에 공격 콘솔의 이전 실행 선택 상태와 가맹점·회원 로그인 상태를 다시 확인한다.

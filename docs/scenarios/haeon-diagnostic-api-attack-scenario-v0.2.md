# HAEON-DIAG-01 — 해온카드 결제 연동 진단 API 침해 시나리오

개정일: 2026-09-22
현재 구현: 가맹점 진단 API · 제한된 웹쉘 흐름 · 탐지·대응 · 회원 보호

## 시나리오 개요

공격자는 해온카드 가맹점 포털에 접속해 결제 연동 진단 API의 입력 처리 취약점을 공략한다. 진단 API에서 제한된 웹쉘 세션이 만들어지면 승인 시스템이 아닌 결제 지원 자료를 조회하고, 내부 수신기로 전송을 시도한다. 보안 운영자는 이벤트 기반 경보를 확인해 해당 세션을 차단하고, 영향 회원에게 추가 확인 안내를 제공한다.

이 흐름은 해온카드 자체 시나리오로 완결된다. 북웨이브나 PG 연동 침해를 선행 조건으로 두지 않는다.

```text
공격자
  ↓ haeon.localhost:8090
가맹점 포털 → 결제 연동 진단 API
                  ↓ 취약 입력 처리
            제한된 웹쉘 세션
                  ↓
       결제 지원 자료 20건 조회
                  ↓
             내부 수신기
                  ↓
       탐지 → 세션 차단 → 회원 보호 안내
```

## 최초 진입점과 정상 업무

최초 진입점은 해온카드의 가맹점 포털에서 제공하는 `결제 연동 상태 진단` 기능이다. 로컬 시연 주소는 `http://haeon.localhost:8090/merchant/`이며 API 경로는 `POST /merchant/v1/diagnostics/connectivity`다.

| 기능 | 경로 | 정상 동작 |
|---|---|---|
| 가맹점 로그인 | `POST /merchant/v1/sessions` | 가맹점 계정 인증 후 30분 세션 발급 |
| 진단 대상 조회 | `GET /merchant/v1/diagnostic-targets` | 로그인한 가맹점에 등록된 대상만 반환 |
| 연결 진단 | `POST /merchant/v1/diagnostics/connectivity` | 등록 대상의 연결 상태와 응답 시간 반환 |

일반 가맹점 계정은 진단 기능만 사용할 수 있다. 회원 로그인과 가맹점 로그인은 분리되어 있고, 지원 서비스 계정에는 `lab_` 자료 테이블 권한만 부여한다. 회원 비밀번호, 승인 내역, 카드 한도에는 접근하지 않는다.

## 침해 경로

시나리오의 최초 취약점은 진단 옵션 입력이 명령 처리 경계에서 안전하게 제한되지 않는 상황이다. 공격 요청은 `status;LAB_SHELL` 마커를 전달한다. 제어 도구에서 실행 모드(`before` 또는 `after`)를 정하며, 일반 가맹점 요청 본문으로 모드를 바꾸지 못한다.

취약 경로가 성립하면 진단 API가 해당 실행 ID와 가맹점에 연결된 제한 세션을 만든다. 세션은 다음 세 동작만 허용한다.

1. 세션 상태 확인
2. 지정된 결제 지원 자료 조회
3. 지정된 내부 수신기로 자료 전송

자료는 회원 `HC-MEMBER-001`과 연결된 마스킹 카드번호 및 합성 거래 20건이다. 다른 URL, 외부 수신지, 파일 업로드, 임의 파일 접근은 받지 않는다. `HC-MEMBER-002`는 보호 안내가 잘못 확장되지 않는지 확인하기 위한 비교 계정이다.

## 실행 순서와 판정 기준

| 단계 | 동작 | 확인할 증거 |
|---|---|---|
| 1. 기준선 | 가맹점 로그인 후 등록 대상 정상 진단 | 인증 주체, 진단 응답, 대상 및 응답 시간 |
| 2. 최초 침입 시도 | 진단 API에 `status;LAB_SHELL` 요청 | 실행 모드, 요청·응답, 실행 ID |
| 3. 웹쉘 세션 | Before에서 발급된 세션으로 자료 조회 | 세션 생성 및 검증 이벤트, 조회 감사 기록 |
| 4. 반출 시도 | 지정 수신기로 20건 JSON 전송 | 송신 응답, 수신 건수, 실행 ID, SHA-256 |
| 5. 탐지·대응 | 경보 확인 후 운영자가 실행 차단 | `ALERT`, 폐기된 세션, 대응 후 재접근 거부 |
| 6. 회원 보호 | 영향 회원 안내 확인 및 비교 계정 점검 | `HC-MEMBER-001` 안내·확인, `HC-MEMBER-002` 미노출 |

### Before

제한된 취약 입력 처리를 통해 세션이 생성되고, 지정 자료 20건을 조회해 내부 수신기로 전송한다. 이벤트에서 침입 징후를 도출해 `ALERT`를 표시한다. 이어서 운영자가 대응 명령을 실행하면 실행 상태를 차단하고 해당 세션을 폐기한다. 이후 같은 세션으로 조회하거나 재전송할 수 없어야 한다.

### After

같은 의미의 비정상 입력을 허용 목록에서 거부한다. 진단 API는 HTTP 403 `DIAGNOSTIC_INPUT_BLOCKED`를 반환하고, 웹쉘 세션 생성·자료 조회·수신기 전송은 발생하지 않는다. 정상 연결 진단은 계속 성공해야 한다. 선행 입력이 차단된 뒤 단계는 성공으로 판정하지 않고 `선행 단계 차단으로 미실행`으로 기록한다.

## 탐지·대응 및 회원 보호

탐지는 실제로 기록된 진단 요청, 세션 생성, 자료 조회, 전송 결과를 기반으로 한다. 정해진 결과를 성공 로그로 출력하지 않는다. 대응은 실행 전체를 차단 상태로 바꾸고 실행에 속한 세션을 폐기한다. 반복 대응은 같은 결과를 유지하며 보호 기록을 중복 생성하지 않는다.

회원 포털은 로그인한 본인에게만 보호 안내를 보여 준다. 조회 대상 회원 `HC-MEMBER-001`에 ‘추가 확인 필요’ 안내를 표시하고, 본인이 확인을 완료한 시각을 기록한다. 안내 확인은 사고 해결이나 결제 정지를 뜻하지 않는다. `HC-MEMBER-002`에는 해당 안내가 나타나지 않아야 한다.

## 증거와 구현 경계

각 실행의 요청·응답·이벤트·수신 결과는 `evidence/runs/<RUN_ID>/`에 저장하고, 민감한 토큰은 화면에 노출하지 않는다. 수신 결과는 같은 실행 ID, 전송 ID, 건수, SHA-256으로 대조한다. 초기화는 현재 시나리오 상태와 보호 안내만 정리하며 저장된 증거와 정상 결제 데이터를 보존한다.

현재 구현은 고정 마커만 처리하는 제한 실행기다. 임의 OS 명령, 실제 웹쉘 설치, 파일 업로드, 실제 카드·회원 정보 조회, 외부 반출을 수행하지 않는다. 문서의 ‘웹쉘’은 지정 API 동작만 허용하는 세션을 가리킨다. 이 경계는 시나리오 결과를 실제 서버 장악으로 과장하지 않기 위한 구현 설명이다.

## 실행 명령

프로젝트 루트에서 실행한다.

```bash
bash tools/haeon-diagnostic-lab.sh normal
bash tools/haeon-diagnostic-lab.sh before
RUN_ID=<Before 실행 ID> bash tools/haeon-diagnostic-lab.sh respond
RUN_ID=<Before 실행 ID> bash tools/haeon-diagnostic-lab.sh verify
bash tools/haeon-diagnostic-lab.sh after
bash tools/haeon-diagnostic-lab.sh reset
```

정상 진단, Before 침입 재현, 대응, After 차단을 각각 다른 실행으로 확인한다. 전체 시나리오 검증은 `http://haeon.localhost:8090/merchant/` 가맹점 화면, `127.0.0.1:8092` 제어 API, 회원 포털 `127.0.0.1:8085`에서 수행한다.

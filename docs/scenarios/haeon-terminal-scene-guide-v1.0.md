# 해온카드 실제 웹사이트 + 독립 가상 터미널 촬영 안내

## 주소와 범위

- 독립 가상 터미널: http://127.0.0.1:8094/terminal-scene.html
- 기존 공격 콘솔: http://127.0.0.1:8094/ (화면·메뉴 변경 없음)
- 실제 해온카드 사이트: http://www.haeoncard.co.kr/
- 실제 가맹점 페이지: http://www.haeoncard.co.kr/merchant/
- 실제 회원 마이페이지: http://www.haeoncard.co.kr/mypage

웹 장면은 **기존 해온카드 사이트 자체**를 촬영합니다. 가상 터미널은 별도의 전체 너비 화면이며, 사이트를 흉내 낸 결과 패널이나 iframe을 포함하지 않습니다. 상단 메인·마이페이지 링크를 누르면 실제 주소가 별도 탭으로 열려 터미널 출력이 유지됩니다. 탭을 전환하거나 탭을 별도 창으로 옮겨 촬영하세요.

터미널은 허용된 명령을 실습 API에 연결합니다. OS 셸이나 실제 웹쉘이 아닙니다. 침해 Before에서 실제 메인 화면이 변조되도록 만들지 않았습니다. 합성자료 접근·내부 전송은 터미널의 응답으로, 대응 후 회원 안내는 실제 마이페이지에서 확인합니다.

기존 콘솔과 실행 기록·모의 세션·회원 보호 안내를 공유합니다. 새 페이지라고 해서 별도의 데이터베이스가 생기거나 기존 상태가 자동 초기화되는 것은 아닙니다. 학생 PC 공개 설정은 추가하지 않았습니다.

## 촬영 전 준비

1. 프로젝트의 기존 Docker Compose 서비스를 기동합니다. 별도 터미널 프로그램 설치는 필요하지 않습니다.
2. 기존 콘솔에서 이전 실행의 대응 대기 여부를 확인합니다. `lab status`로도 확인할 수 있습니다.
3. 깨끗한 새 촬영이 필요하면 증거를 보관한 뒤 **기존 콘솔의 시연 상태 초기화**를 직접 사용합니다. 이 버튼은 실제 실습 이력·세션·안내를 초기화하므로 주의합니다.
4. 메인·마이페이지·가상 터미널을 각각 별도 탭에 준비합니다. 회원 안내를 촬영하려면 마이페이지에서 HC-MEMBER-001에 해당하는 기존 실습 회원으로 로그인해 둡니다. 명령어 시연 자체에는 수동 가맹점 로그인이 필요하지 않습니다. 기존 서버가 지정된 실습 가맹점 계정으로 API 인증을 수행합니다.
5. 명령어 안내를 클릭하면 입력창에 명령만 채워집니다. Enter 또는 실행 버튼으로 실행합니다. 촬영 모드는 설명 영역을 숨길 뿐 검증이나 결과를 변경하지 않습니다. 터미널은 시작 배너 없이 빈 출력으로 열리고, 입력 명령과 결과·오류만 표시합니다. 사용 안내가 필요할 때만 `help`를 입력하세요.

## 권장 촬영 순서

| 순서 | 입력/화면 | 설명할 내용 |
|---|---|---|
| 1 | 실제 메인 탭: `http://www.haeoncard.co.kr/` | “시연 대상은 기존 해온카드 웹사이트입니다.” 메인 화면을 소개한다. |
| 2 | 실제 마이페이지 탭: `/mypage` | 로그인 후 현재 회원 화면을 보여준다. 깨끗한 Before 촬영은 기존 콘솔에서 명시적으로 초기화한 뒤 진행한다. 과거 보호 안내가 남아 있다면 정상 초기 상태라고 설명하지 않는다. |
| 3 | 터미널 탭으로 전환 → `lab baseline` | “가맹점의 정상 연결 진단부터 확인하겠습니다.” |
| 4 | 터미널: `lab before` | “제한된 모의 세션에서 합성자료 조회와 내부 수신기 전송 흐름을 재현합니다.” 생성·조회·전송은 묶음 실행이며 실제 OS 명령 실행은 없다. |
| 5 | 터미널: `lab records` | 같은 세션으로 자료를 **추가 조회**한다. 합성 회원 ID·카드 끝 4자리·거래 참조·금액 표를 충분히 보여준다. |
| 6 | 터미널: `lab receipt` | 같은 실행 ID의 RECEIVED, 건수, 전송 ID, SHA-256을 확인한다. 터미널이 외부 수신기라는 뜻은 아니다. |
| 7 | 터미널: `lab contain` | “방어자 대응으로 해당 세션을 폐기합니다.” 동일 세션 재조회·재전송 거부와 보호 안내 등록 결과를 확인한다. |
| 8 | **실제 마이페이지 탭으로 전환 → 새로고침** | “실제 회원 페이지에 보호 안내가 반영됐는지 확인합니다.” 해당 회원의 안내를 촬영한다. 안내는 실제 카드 정지나 사건 종결과 다르다. 등록 실패가 출력됐다면 성공 장면으로 설명하지 않는다. |
| 9 | 터미널 탭으로 복귀 → `lab records` | “같은 세션의 재접근은 HTTP 403으로 거부됩니다.” 이전에 표시된 자료가 소급 삭제된다는 뜻은 아니다. |
| 10 | 터미널: `lab after` | **별도의 개선 설정**에서 같은 비정상 진단 입력의 403 차단과 정상 진단의 200 유지를 확인한다. 대응 명령이 운영 환경에 패치를 배포하는 것은 아니다. |
| 11 | 터미널: `lab compare` | 연결된 Before·After 표를 보여주며 마무리한다. 필요하면 기존 공격 콘솔의 결과 비교 화면으로 이동한다. |

실제 페이지 탭은 터미널이 자동으로 새로고침하거나 다른 주소로 이동시키지 않습니다. 촬영자가 필요한 시점에 탭을 전환하고 새로고침합니다. 메인 사이트는 서비스 소개용이며, 이 시나리오의 화면 변화 확인 지점은 **회원 보호 안내가 등록된 마이페이지**입니다.

`Before`의 전체 침해 흐름은 기존 API가 한 번에 실행합니다. `lab records`와 `lab receipt`는 침입 단계와 전송 단계를 새로 분리해 실행하는 명령이 아니라, 결과를 더 자세히 관찰하기 위한 명령입니다. 과장된 단계별 성공 화면을 고정 재생하지 않습니다.

## 보조 시연: CARD-03

주 시나리오의 실행과 대응을 마친 후 `lab card03`를 입력하면 기존 동시 승인 실험 API를 호출합니다. 한도 100,000원인 분리 장부에서 서로 다른 60,000원 거래 2건을 비교합니다. 현재 승인 코어 자체 또는 북웨이브↔PG 연동 공격 시험이 아닙니다.

## 명령어 및 오류 처리

- `help`: 허용된 명령어 목록.
- `lab status`: 서비스 연결, 기준선, 현재 Before, 연결된 After, 대응 대기 상태.
- `clear`: 확인 문구 없이 현재 터미널 표시를 완전히 비웁니다. 실습 데이터·회원 안내·세션은 유지됩니다.
- 위/아래 화살표: 이 페이지에서 입력한 명령 이력. Tab: 일치하는 명령이 하나일 때 완성.
- 로그 저장: 현재 화면의 출력과 합성자료 표를 TXT로 다운로드합니다. 비공개 세션 토큰은 포함하지 않습니다.
- 새로고침: 최근 서버 기록을 다시 불러옵니다. 터미널의 이전 입력/출력은 자동 복원하지 않으므로 먼저 로그를 저장합니다.
- 연결 실패, 응답 불일치, 타임아웃은 오류로 표시하며 자동 재실행하지 않습니다. `lab status`나 기존 콘솔에서 실제 상태를 확인합니다.
- 임의 URL, 파일 경로, OS 명령, 스크립트, 파이프/명령 연결은 지원하지 않습니다.

## 구현/검증 참고

원래 index/filming/demo-terminal 화면과 기존 API 계약은 유지했습니다. 새 정적 파일 4개와 `POST /api/terminal/records`만 추가합니다. 이 고정 경로는 서버에 이미 저장된 해당 Before의 비공개 세션을 이용해 실습 자료를 조회하고, 합성 식별자·필드·건수·카드 끝 4자리를 검증한 뒤 허용 필드만 반환합니다. 응답과 로그에 세션 토큰을 내보내지 않습니다.

오프라인 검증: `python -B -m unittest test_server test_filming test_terminal_records`, `node test_terminal_scene.cjs` (services/haeon-attack-console 폴더에서 실행).

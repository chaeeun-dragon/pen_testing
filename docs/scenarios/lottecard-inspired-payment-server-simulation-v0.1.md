# 실제 카드사 침해사고 착안 결제 서버 침해 시뮬레이션과 CARD-03 연결 v0.1

작성일: 2026-09-16
상태: S1~S4 순서 로그·탐지와 실행 증거 패키지 구현·검증됨 — 실제 침입·웹쉘은 미구현·비범위
대상: 북웨이브 → Mock PG → 해온카드 합성 결제 실습 환경

## 1. 이 문서가 정하는 프로젝트 표현

이 프로젝트는 사회적으로 이슈가 된 카드사 침해사고에서 **결제 서버 침입과
정보보호 대응의 문제의식**을 가져와, 실제 고객·카드·PG를 전혀 쓰지 않는 격리된
합성 환경에서 일부 보안 통제와 증거 흐름을 검증한다.

현재 구현 범위의 발표에서는 다음처럼 표현한다.

> 실제 카드사 사건에서 드러난 온라인 결제 서버 침입·정보유출 위험을 참고하여,
> 컨테이너 격리·구조화 상관관계 로그·탐지 자동화로 구성한 합성 결제 환경에서
> 카드 승인 코어의 정합성 방어를 검증했고, 별도의 전용 경로에서 고정된 결제 서버
> 침입 징후를 합성해 탐지·차단 증거를 남긴다.

전용 경로의 실행 증거와 회귀 검증을 완료한 뒤에만 다음 표현으로 바꿀 수 있다.

> 공개된 카드사 침해사고의 결제 서버 침입·정보유출 위험을 참고하여, 합성·격리
> 환경에서 침입 징후의 탐지·차단과 카드 승인 코어의 정합성 방어를 검증했다.

다음 표현은 사용하지 않는다.

- “롯데카드와 동일한 취약점을 재현했다.”
- “실제 웹쉘을 운영 환경과 동일하게 구현했다.”
- “실제 고객정보 유출 또는 실제 부정결제를 재현했다.”

공개 조사 내용의 범위를 넘어서 원인·공격 도구·피해를 단정하지 않는다.

## 2. 공개 사실과 합성 시나리오의 경계

### 2.1 공개 자료로 확인할 수 있는 사실

금융위원회 공개 자료는 2025년 롯데카드 온라인 결제 서버(WAS) 침입과 웹쉘 설치,
정보 유출 정황을 설명한다. 후속 제재 의결 자료에는 패치 작업, 주민등록번호·비밀번호
암호화, 백신 소프트웨어 관리 관련 보안의무 위반 사항이 명시되어 있다.

- 사고 경위·소비자 보호 조치: <https://fsc.go.kr/edu/news/85349>
- 제재 의결·보안의무 위반 사항: <https://www.fsc.go.kr/po010107/87455?curPage=4&srchBeginDt=&srchCtgry=&srchEndDt=&srchKey=&srchText=>

이 문서의 설계는 위 공개 사실의 **침해 표면과 대응 필요성**만 참고한다. 공개 자료는
동시 승인 한도 이중 사용을 해당 사고의 원인 또는 실제 피해로 확정하지 않는다.

### 2.2 이 프로젝트에서 합성하는 부분

| 구분 | 실제 사건과의 관계 | 실습에서의 처리 |
|---|---|---|
| 결제 서버 침입 징후 | 공개 사건에서 참고 | 안전한 이벤트·로그 시뮬레이션으로만 설계 |
| 웹쉘 | 공개 자료에 언급됨 | 명령 실행 기능이나 재사용 가능한 웹쉘은 만들지 않음 |
| 고객·카드 데이터 | 실제 사고는 정보유출 사건 | fixture의 합성 식별자·합성 카드 토큰만 사용 |
| 부정결제 | 공개 자료가 당시 확정한 직접 피해와 구분 필요 | 실제 금전 이동 없이 승인 정책·탐지 결과만 검증 |
| CARD-03 한도 경쟁 | 실제 사건의 직접 원인으로 주장하지 않음 | 독립적인 승인 코어 무결성 방어 시나리오로 유지 |

## 3. 현재 완료된 CARD-03의 위치

CARD-03은 정상 형식의 서로 다른 승인 요청 두 건이 동일 카드 한도를 동시에 읽을 때
발생할 수 있는 상태 무결성 문제를 검증한다.

```text
정상 결제 요청 A/B
  → Mock PG 신뢰 경계
  → 해온카드 한도 판정
  → Before: 두 건 승인 / 한도 초과 ALERT
  → After: 행 잠금·최신 값 재판정 / 한 건 거절 PASS
```

현재 구현·증거가 직접 뒷받침하는 범위는 다음과 같다.

- 북웨이브 → Mock PG → 해온카드의 합성 결제 왕복
- `correlationId`를 이용한 세 서비스 로그 연결
- 동일 멱등키의 동시 요청·재조회에서 동일 결과 반환
- CARD-03 Before의 한도 초과 `ALERT`와 After의 한도 차단 `PASS`
- `used_amount`, `version`, 승인·거래·감사 이벤트의 대사

CARD-03은 침입 이후의 부정결제 경로를 증명하는 자료가 아니다. 카드 승인 코어가
동시 요청에도 정합성을 유지하는지를 보여 주는 **방어 심화 시나리오**다.

### 3.1 구현 전 기준선과 실행 차단 장치

2026-09-16에 새 시나리오 구현 전 기준선을 다시 확인했다.

- `PRE-INCIDENT-CARD-20260916T011617Z`: 해온카드 승인·재조회·한도 초과 거절,
  요청 결과 필드 무시, 잘못된 Bearer·누락 Bearer의 `403` 확인
- `PRE-INCIDENT-FLOW-20260916T011641Z`: 북웨이브 → Mock PG → 해온카드의 같은
  멱등키 동시 2건·재조회 응답 일치와 세 서비스 `correlationId` 연결 확인
- `PRE-INCIDENT-FLOW-20260916T011641Z-DETECTION`: 지정된 실행 범위의 탐지 결과 `PASS`
- `PRE-INCIDENT-CONTRACT-20260916T012143Z`: 기본 비활성화 가드를 포함해 재빌드한
  Bookwave에서도 전체 결제 계약이 통과했고, 대응 탐지 결과
  `PRE-INCIDENT-CONTRACT-20260916T012143Z-DETECTION`는 `PASS`

증거는 각각 `evidence/runs/<실행ID>/`에 보관한다. 검증이 끝난 뒤 합성 카드 DB는
한도 100,000원, `used_amount=0`, `version=0`으로 복원했다.

침입 징후 시뮬레이션은 기본 비활성화 상태다. `INCIDENT_SIMULATION_ENABLED=false`인
기본 배포에서는 `403 INCIDENT_SIMULATION_DISABLED`로 거절한다. 활성화하더라도
`INCIDENT-SIM-` 형식의 합성 실행 ID와 별도의 랩 제어 토큰을 모두 통과해야 한다.
전용 경로는 `POST /internal/v1/lab/incident-simulations/payment-server`이며 결제 본문·
가맹점·카드·명령을 받지 않는다. 구현은 고정 이벤트 일곱 개만 기록하며 Mock PG·
해온카드를 호출하지 않는다. 세부 계약은
`docs/contracts/incident-simulation-contract-v0.1.md`를 따른다.

전용 경로의 S1~S4·증거 패키지 최종 검증 실행은 `INCIDENT-SIM-20260916T030000Z`로
남겼다. S3 `ALERT`, S4 `BLOCKED`·추가 검증 `PASS`를 포함한 고정 이벤트 일곱 개가
Bookwave 로그에서만 확인됐고, 범위 제한 탐지·독립 증거 검사 결과는 모두 `PASS`였다.
응답·증거 모두
`mockPgCalled=false`, `haeonCardCalled=false`였다. 이후
`POST-EVIDENCE-FLOW-20260916T034500Z`로 정상 결제 동시 멱등성 회귀를 통과했으며,
최종 합성 카드 DB는 한도 100,000원, 사용액 0원, 버전 0으로 복원했다.

## 4. 구현된 최소 시나리오: 결제 서버 침입 징후의 안전한 시뮬레이션

이 시나리오는 기존 CARD-03을 훼손하지 않는 별도 랩 제어 경로로 구현했다. 실제 공격
동작을 만들지 않고, 입력에 따라 행동이 달라지지 않는 고정 합성 신호만 기록한다.

```text
[S0] 정상 기준선
  → [S1] 결제 서버의 비정상 접근 징후(합성 이벤트)
  → [S2] 합성 결제 데이터 접근 또는 내부 승인 호출 시도
  → [S3] 구조화 로그·탐지 규칙으로 ALERT
  → [S4] 차단·추가 검증 후 정상 결제 PASS
  → [S5] 독립 실행한 CARD-03 After로 승인 코어 정합성 확인
```

### 4.1 각 단계의 의미와 금지 범위

| 단계 | 시연할 사실 | 허용되는 구현 | 금지되는 구현 |
|---|---|---|---|
| S0 | 기준선이 정상임 | 합성 fixture, health check, 정상 결제 | 실제 개인정보·금융망 연결 |
| S1 | 결제 서버 침입 징후 | 고정 `simulated_payment_server_access_detected=OBSERVED` 이벤트 | 명령 실행 가능한 웹쉘, 외부 노출 |
| S2 | 데이터 접근 위험 | 고정 `simulated_synthetic_data_access_attempted=OBSERVED` 이벤트. 실제 접근은 수행하지 않음 | 실제 카드번호·CVC·인증정보 저장·반출 |
| S3 | 탐지 가능성 | `incident_simulation_alert_raised=ALERT`, `runId`·`correlationId` 범위 제한 탐지 | 전체 DB를 무차별 스캔하거나 실제 공격 도구 사용 |
| S4 | 대응 효과 | 고정 `BLOCKED`와 `incident_simulation_additional_verification_passed=PASS`, PG·카드 호출 없음 대사 | 실제 계정 차단·실제 결제 취소 |
| S5 | 승인 코어 방어 | 기존 CARD-03 Before/After를 별도 실행·대사 | 침입 단계와 CARD-03 결과를 같은 원인이라고 단정 |

### 4.2 최소 증거 계약

전용 실행 도구는 한 실행 ID 아래에 다음을 만들며, 기존 CARD-03 증거 형식과
충돌하지 않는다.

- `scenario.json`: `scenarioId`, `simulation=true`, Mock PG·해온카드 호출 없음
- `request.json`: 제어 토큰을 `redacted`로 마스킹한 전용 경로 실행 요청
- `bookwave-health.json`: 실행 전 Bookwave 상태
- `services.log`: S1~S4의 `correlationId`별 고정 구조화 이벤트
- `result.json`: S3 `ALERT`, S4 차단·추가 검증 `PASS`
- `detection/result.json`, `event-sequence.tsv`: 범위 제한 탐지 결과와 순서 대사
- `summary.txt`: 합성 데이터만 사용했으며 실제 웹쉘·실제 정보유출이 아니라는 문구
- `correlation-report.tsv`: 북웨이브만 상관 로그가 있고 Mock PG·해온카드는 없음
- `evidence-check.json`, `evidence-manifest.json`: 필수 증거 검증과 파일별 SHA-256 대사

## 5. 최신 기술과의 연결 기준

이 프로젝트가 “최신 기술과 결합한 재현”으로 평가받으려면 최신이라는 표현을
유행어가 아니라 검증 가능한 구현 요소에 붙인다.

| 요소 | 현재 상태 | 프로젝트 기여 |
|---|---|---|
| Docker Compose 네트워크 격리 | 구현됨 | 결제·PG·카드 DB 경계를 분리한 안전한 실습 환경 |
| Spring Boot 기반 서비스 분리 | 구현됨 | 서비스 간 신뢰 경계와 API 계약을 검증 |
| 구조화 로그와 `correlationId` | 구현·검증됨 | 다중 서비스 거래와 보안 이벤트의 추적성 |
| 범위 제한 탐지 자동화 | 구현·검증됨 | 실행 단위 DB·로그 대사와 증거 재현성 |
| 침입 징후 시뮬레이션 | 구현·검증됨 | 전용 비결제 경로에서 고정 ALERT·BLOCKED·PASS 증거를 생성 |

현재 단계에서 인공지능 탐지, OpenTelemetry, 실제 EDR을 사용한다고 주장하지 않는다.
필요하면 후속 범위로 추가하되, 도입 전후의 탐지 근거와 비용을 별도로 검증한다.

## 6. MITRE ATT&CK 표현 원칙

현재 CARD-03의 매핑은 `T1565.003`의 조건부 해석에 한정하며, 침입 기법은 아직
실행하지 않았으므로 추가 ATT&CK 기법을 확정하지 않는다.

후속 S1~S4가 구현되더라도 “웹쉘”이라는 이름만으로 `T1505.003 Web Shell`을
확정하지 않는다. 안전한 합성 이벤트만 기록한다면 ATT&CK 기법이 아니라
**사건 참고용 탐지 시뮬레이션**으로 표기한다. 공개 서비스 취약점 악용을 실제로
검증하지 않는 한 `T1190 Exploit Public-Facing Application`도 매핑하지 않는다.

## 7. 최종 발표 구조

1. 실제 카드사 침해사고의 공개 사실과 프로젝트의 합성·격리 범위를 먼저 설명한다.
2. 북웨이브 → Mock PG → 해온카드의 정상 결제와 `correlationId`를 보여 준다.
3. 전용 시뮬레이션의 침입 징후 `ALERT`와 고정 차단·대응 결과를 제시한다.
4. CARD-03 Before `ALERT`와 After `PASS`를 별도 카드 승인 코어 방어 증거로 제시한다.
5. 실제 정보유출·실제 금전 피해·동일 취약점 재현을 주장하지 않는다는 한계를 명시한다.

이 구조라면 프로젝트는 실제 사건을 자극적으로 모사하는 작업이 아니라,
**공개된 사건의 보안 교훈을 현대적인 컨테이너 분리·관측성·탐지 자동화로 검증하는
안전한 합성 재현**으로 설명할 수 있다.

# 해온카드 최종 발표 시연 v1.1

기준: `v0.8_slides.pdf` p.23, p.27, p.34 / 보안 가이드 v1.1 p.5-6, p.8.
원본 발표 슬라이드와 보안 가이드는 수정하지 않았다. 촬영용 PDF는 이 문서와 실제 실행 화면을 바탕으로 별도 제공한다.

## 화면과 공개 범위

- 해온카드: http://127.0.0.1:8090/
- 가맹점: http://127.0.0.1:8090/merchant/
- 마이페이지: http://127.0.0.1:8090/mypage
- 발표 시연 데스크: http://127.0.0.1:8094/
- 결과 전용: http://127.0.0.1:8094/filming.html?view=results
- 이전 상세 콘솔: http://127.0.0.1:8094/index.html

콘솔과 제어 API는 호스트 loopback 전용이다. 학생용 80/8090 포트에서는 콘솔 도메인과 `/lab-shell/`, `/control/`, `/internal/`를 404로 거절한다. `console.haeoncard.co.kr` DNS 레코드를 지우지는 않았으며 더 이상 콘솔 진입점으로 사용하지 않는다. 카드 사이트의 기존 선택형 classroom LAN 매핑은 유지한다.

## 촬영 전 준비

Docker가 이미 기동·빌드 완료된 상태에서 촬영을 시작한다. `docker compose -d --build`가 아니라 `docker compose --env-file .env up -d --build`가 올바른 기본 명령이다. 본 수정은 실행 중인 서비스에 적용 완료했다. 평소에는 콘솔 연결 표시만 확인하면 된다.

기존 DB를 가진 다른 PC에 배포하는 경우 `011_card03_lab.sql`을 한 번 적용해야 한다. 새 볼륨에서는 compose 초기화 스크립트가 자동 적용한다. 초기화를 위해 `docker compose down -v`를 실행하지 않는다.

가맹점 합성 계정: `labmart` / `LabMart!2026`. 영향 회원: `haeon01` / `Haeon!2026`. 비교 회원: `haeon02` / `Haeon!2026`. 로그인 입력은 녹화 전 수행하거나 편집에서 제외한다. 실제 계정이 아니다.

## 주 시연 HAEON-DIAG-01 (약 3분)

1. 해온카드 메인을 5초 보여준다. “해온카드의 가맹점 결제 연동 진단 기능을 검증합니다.”
2. 발표 시연 데스크를 열고 주 시연과 보조 실험이 별도임을 보여준다.
3. 가맹점 페이지에 로그인 → 등록 대상 `해온마트` 선택 → 정상 연결 진단 실행. 실제 HTTP 연결 정상임을 보여준다.
4. 데스크로 돌아와 `정상 진단` 버튼을 누른다. 이 실행은 Before와 연결할 기준선이다.
5. `Before 실행`을 누른다. 가맹점 인증, 고정된 등록 대상, `status;LAB_SHELL`이라는 고정 실습 입력, 제한된 세션, 합성 자료 조회, 내부 수신기 전송을 차례로 실제 호출한다. 별도의 임의 명령 입력은 없다.
6. 결과 전용 화면에서 Before `20건 조회`와 `20건 · RECEIVED`를 각각 설명한다. 증적을 펼쳐 전송 ID와 SHA-256을 보여준다. “ALERT는 탐지되었다는 뜻이지, 전송이 차단되었다는 뜻은 아닙니다.”
7. 데스크로 돌아와 `대응 및 재접근 검증`을 누른다. 같은 Before 세션의 재조회·재전송이 각각 403인지 확인한다. 세션 토큰은 화면·공개 JSON에 노출하지 않는다.
8. 마이페이지에 영향 회원으로 로그인해 추가 확인 안내를 보여준다. “합성 지원 자료 접근이 관측된 회원에게 안내가 등록됐습니다. 확인 버튼은 읽음 기록만 남깁니다.” 실제 문자/메일 전송이나 카드 정지는 하지 않는다. 필요하면 영향 없는 `haeon02`와 비교한다.
9. 데스크에서 `After 실행`을 누른다. 동일 입력 403, 후속 단계 미실행, 정상 진단 HTTP 200을 보여준다. Before의 세션 폐기와 After의 입력 허용 목록은 서로 다른 검증이다. 버튼을 눌러 실제 코드를 패치한 것이 아니라 미리 구성한 두 실습 경로를 비교한다.
10. 결과 전용 화면에서 한 장으로 정리한다. 전체 방어선이나 실제 악성 웹쉘 설치를 검증했다고 말하지 않는다.

## 보조 CARD-03 (약 40초, 선택)

`02 CARD-03 · 보조 실험` → `동시 승인 Before / After 실행`.

- 합성 한도 100,000원, 서로 다른 TX-1/TX-2 각 60,000원.
- Before는 두 MySQL 트랜잭션의 과거 값 읽기 시점을 barrier로 맞춘다. 두 건 승인, 장부 사용액 120,000원.
- After는 같은 합성 한도 행을 `SELECT ... FOR UPDATE`로 잠근다. 한 건 승인, 한 건 거절, 사용액 60,000원.
- 별도 정상 승인·동일 요청 재시도·다른 내용의 키 재사용·한도 초과 거절도 확인한다.
- 범위: `lab_card03_limits`, `lab_card03_approvals`라는 격리된 MySQL 실험 장부. 기존 카드 승인 코어를 취약하게 변경하지 않았다. Mock PG 경유나 북웨이브 주문 상태 대조의 통합시험도 아니다.
- 발표 슬라이드에는 “CARD-03: 격리 합성 장부의 동시성 통제 비교”라고 덧붙인다. 현 승인 코어 취약점 발견 또는 PG 공격 성공으로 소개하지 않는다.

## 재촬영·증거

데스크에서 `증거 JSON ↓`로 결과를 보관한 다음 `시연 상태 초기화`를 확인한다. 실습 실행·세션·이벤트·보호 안내·가맹점 로그인·콘솔 이력만 초기화된다. 정상 결제 데이터와 `evidence/` 파일은 유지된다. CARD-03 합성 DB 장부는 검증 근거로 유지되며 새로운 비교는 항상 독립 장부로 시작한다. 초기화 뒤 가맹점 로그인부터 다시 시작한다.

자동 증거: `evidence/console/<실행 ID>.json`. 수신기: `evidence/receiver/`. 검증 도구: `tools/haeon-ux-scenario-check.py --faults` (실습 상태를 생성하고 서비스 일시 중지/재시작). 원시 CLI `attack-response.json`에는 실습 세션 토큰이 있어 촬영하지 않는다.

`tools/payment-server-incident-simulation.sh`는 북웨이브 계열의 별도 고정 이벤트 시뮬레이션이므로 이 해온카드 시연에 사용하지 않는다. 터미널 장면은 선택 사항이며 브라우저만으로 주 시연을 완주할 수 있다.

## 백업과 복원

원본 폴더: `C:\study\docker\bookwave-haeon-lab-backup-20260929-pre-filming`.
전체 1,273개 파일을 SHA-256 비교로 검증했다. `.git`, `.env`, 기존 미커밋·미추적 파일을 포함한다.
`_runtime/haeon-card.sql`은 변경 전 해온 DB 덤프, `_runtime/console-state.json`은 이전 콘솔 이력이다. 기존 해온 이미지 4개는 `:pre-filming-20260929` 태그로 Docker에 보존했다.

소스만 되돌릴 때: 관련 서비스 중지 → 현재 폴더를 다른 이름으로 보관 → 백업 폴더를 원래 경로로 **복사** → 관련 서비스 재빌드. 백업 자체를 이동하거나 덮어쓰지 않는다. `.env` 포함 백업은 외부에 공유하지 않는다.

DB·콘솔 상태까지 되돌리는 별도 복원은 현재 결과를 덮어쓰므로, 먼저 현재 DB와 `/data`를 다시 백업한다. `_runtime` 덤프를 해온 DB에 가져오고 콘솔 상태를 복원한 뒤 실행한다. 폴더 교체만으로 Docker 볼륨이 되돌아가지는 않는다. `RESTORE.md`의 상세 절차를 따른다.

시나리오 흐름

공격자는 해온카드 도메인에서 가맹점 인증을 거쳐 진단 API에 접근합니다. 북웨이브나 PG 연동은 이 흐름의 선행 단계가 아닙니다.

가맹점 로그인›정상 진단›취약 입력›자료 접근·전송›탐지·대응

녹화 전 확인

  • 가맹점 화면: http://haeon.localhost:8090/merchant/
  • 회원 보호 화면: 포털 127.0.0.1:8085
  • 제어 API: 127.0.0.1:8092 로컬 전용
  • 터미널에는 실행 ID만 표시하고 토큰은 가립니다.
1

가맹점 로그인과 정상 진단

등록 대상에 대한 정상 업무가 먼저 동작하는지 보여 줍니다.

브라우저

화면 동작

  1. 가맹점 포털에서 계정으로 로그인합니다.
  2. 등록된 진단 대상을 선택해 연결 상태를 확인합니다.
  3. 정상 응답과 소요 시간을 화면에서 확인합니다.

확인할 점

진단은 결제 승인이나 취소를 만들지 않습니다. 회원 화면과 가맹점 세션이 분리되어 있음을 설명합니다.

“외부 공격자는 해온카드 가맹점 포털의 진단 기능에서 시작합니다. 먼저 같은 기능이 정상 요청을 처리하는 기준선을 확인하겠습니다.”
2

최초 진입과 웹쉘 세션 생성 · Before

진단 입력 처리 취약 경로에서 제한 세션이 만들어지는 흐름을 확인합니다.

공격자

시연 순서

  1. before 실행을 생성합니다.
  2. 가맹점 진단 API에 고정 입력을 보냅니다.
  3. 응답의 실행 ID로 세션과 후속 결과를 연결합니다.
프로젝트 루트 · 실행 ID는 출력값 사용
bash tools/haeon-diagnostic-lab.sh before
RUN_ID=<출력된 실행 ID> bash tools/haeon-diagnostic-lab.sh verify

방어자 관찰

  1. 인증된 가맹점 세션의 진단 요청을 확인합니다.
  2. 새 웹쉘 세션 생성 이벤트에 경보가 연결됩니다.
  3. 진단 API가 전달한 실행 ID와 상관 ID를 기록합니다.
Before 판정ALERT
세션생성
조회 자료20건
전송 대상내부 수신기
“최초 침입점은 결제 연동 진단 API입니다. 제한 세션은 지정된 자료 조회와 내부 수신만 허용하며, 뒤의 증거를 동일 실행 ID로 대조하겠습니다.”
3

자료 접근·전송과 자동 탐지

API 응답과 수신 기록을 연결해 실제 처리 결과를 확인합니다.

증거 대조

공격자 화면

  1. 제한 세션으로 결제 지원 자료 조회를 요청합니다.
  2. 같은 실행 ID의 전송 응답을 확인합니다.
  3. 자료 건수와 SHA-256을 수신 기록과 비교합니다.

방어자 화면

  1. 세션 생성·자료 조회·전송 이벤트를 확인합니다.
  2. 수신 기록의 실행 ID와 건수가 일치하는지 대조합니다.
  3. 관측된 비정상 이벤트에서 생성된 ALERT를 확인합니다.
운영 화면에서 제어 토큰이나 세션 원문을 공개하지 않습니다. 실행별 자료는 evidence/runs/<RUN_ID>/에 남습니다.
4

운영자 대응과 세션 폐기

자동 경보 확인 뒤 운영자가 대응을 실행해 후속 접근을 막습니다.

방어자
실행 ID를 지정해 대응하고 결과 검증
RUN_ID=<Before 실행 ID> bash tools/haeon-diagnostic-lab.sh respond
RUN_ID=<Before 실행 ID> bash tools/haeon-diagnostic-lab.sh verify
실행 상태CONTAINED
경보 상태BLOCKED
기존 세션폐기
재접근거부
“경보는 이벤트에 따라 자동 생성됐고, 차단과 세션 폐기는 운영자가 수행했습니다. 대응 완료 후 기존 세션을 재사용할 수 없습니다.”
5

개선 후 동일 입력 차단 · After

정상 진단은 유지하면서 비정상 옵션을 거부하는지 확인합니다.

통제 확인

시연 순서

  1. after 실행을 새로 생성합니다.
  2. 같은 의미의 비정상 진단 요청을 전달합니다.
  3. HTTP 403과 DIAGNOSTIC_INPUT_BLOCKED를 확인합니다.
프로젝트 루트
bash tools/haeon-diagnostic-lab.sh after
bash tools/haeon-diagnostic-lab.sh normal

판정

공격 요청403 BLOCKED
세션 생성없음
수신 자료없음
정상 진단SUCCESS

첫 단계에서 차단된 뒤의 공격 단계는 성공으로 기록하지 않고 미실행으로 표시합니다.

6

회원 보호 안내와 확인 기록

영향 회원만 본인 인증 후 안내를 확인할 수 있는지 점검합니다.

회원 포털

영향 회원

haeon01로 로그인해 추가 확인 안내와 발생 시각을 보여 주고 확인 완료를 기록합니다.

비교 회원

haeon02로 로그인해 동일 안내가 표시되지 않는 것을 확인합니다. 비로그인 사용자는 회원 안내 API에 접근할 수 없습니다.

“확인 완료는 안내를 읽었다는 기록입니다. 사고 해결이나 결제 정지를 의미하지 않습니다.”

촬영 마무리

화면에 남길 결과: 정상 진단 → Before ALERT → 수신 자료 20건 → 대응 후 CONTAINED/BLOCKED → After 403 → 회원 안내 확인.

기술적으로는 제한 마커만 처리하며 임의 OS 명령을 실행하지 않습니다. ‘웹쉘 세션’은 지정 API 동작만 가능한 접근 세션입니다.

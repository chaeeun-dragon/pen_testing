공격 콘솔 촬영 큐시트

공격 콘솔의 실행 제어, 단계 결과, 보안 이벤트 로그를 중심으로 정상 진단부터 Before, 대응, After, 회원 보호까지 한 흐름으로 촬영합니다.

준비정상 진단Before탐지·증거대응After회원 보호정리

촬영 흐름

공격 콘솔의 왼쪽 메뉴에서 해온카드 시나리오를 선택하고, 오른쪽의 실행 요약·단계 제어·상세 근거 로그·Before/After 비교를 촬영합니다. 로그는 한 글자씩 순차 표시되므로 결과가 완성되는 장면까지 기다립니다. 가맹점 포털은 정상 업무와 진입 기능 확인 화면, 회원 포털은 대응 결과 확인 화면으로 사용합니다.

가맹점 정상 업무→콘솔 정상 진단→Before→대응→After→회원 안내

브라우저 탭 준비

공격 콘솔: http://haeon-attack.localhost:8090/

시연 터미널: http://haeon-attack.localhost:8090/demo-terminal.html

가맹점 포털: http://haeon.localhost:8090/merchant/

회원 마이페이지: http://haeon.localhost:8090/mypage

시연 터미널의 주 버튼은 기준선 확인 → 공격자 Before → 방어자 대응·After → 회원 보호 순서로 바뀝니다. 터미널은 단계 묶음마다 새 세션 화면으로 전환됩니다. 00–01은 환경 확인·정상 진단, 02–03은 Before·증거, 04는 대응, 05는 After, 06은 회원 보호 화면입니다. 전환할 때 이전 로그를 지우고 제목과 단계 번호를 새로 표시해 스크롤이 누적되지 않게 합니다. 로그가 한 글자씩 표시되는 동안은 기다리고, 각 버튼 단계가 끝난 뒤 발표자가 다음 장면으로 진행합니다. 이전 Before 실행이 대응 대기 중이면 새 재생을 시작하지 않습니다. 북웨이브와 PG 메뉴는 이후 독립 시나리오를 위한 자리입니다. 이번 촬영에서는 해온카드만 실행하고, 비밀번호·제어 토큰·세션 원문은 화면에 표시하지 않습니다.

서비스 기동과 화면 준비

해온카드 구성과 공격 콘솔이 모두 준비되었는지 확인합니다.

촬영 전

터미널 · 프로젝트 루트

docker compose --env-file .env up -d --build haeon-lab-gateway
docker compose --env-file .env ps haeon-attack-console haeon-card haeon-merchant-support haeon-lab-receiver haeon-lab-gateway

목록의 상태가 모두 healthy인 장면만 짧게 남깁니다.

카메라 구도

  1. 주 화면은 공격 콘솔로 둡니다.
  2. 가맹점 포털에서 로그인과 정상 연결 확인을 짧게 보여 줍니다.
  3. 회원 보호는 대응 후 별도 탭에서 확인합니다.
  4. 콘솔 이력은 남을 수 있으므로 이번 촬영에서 만든 실행 ID를 선택합니다.

정상 업무와 기준선

가맹점 정상 진단과 콘솔의 정상 진단이 같은 등록 대상에서 성공하는지 확인합니다.

정상 업무

가맹점 포털

  1. 가맹점 계정으로 로그인합니다.
  2. 등록된 진단 대상에서 연결 상태 확인을 실행합니다.
  3. 정상 상태와 응답 시간을 촬영합니다.

공격 콘솔

  1. 해온카드 시나리오 개요에서 대상 상태가 준비되었는지 확인합니다.
  2. 정상 진단을 선택합니다.
  3. 가맹점 지원 계정 인증 → 등록 진단 대상 확인 → 진단 요청 전송 → 등록 대상 연결 진단 단계가 완료되는 장면을 촬영합니다.
“정상 기준선은 등록된 내부 진단 대상에 대한 연결 확인입니다. 결제 승인이나 취소를 실행하지 않습니다.”
2

Before 공격 흐름 실행

공격 콘솔에서 제한된 진단 입력 처리와 모의 웹 세션 흐름을 실행합니다.

공격 경로

콘솔 조작

  1. Before 공격 흐름을 선택합니다.
  2. 진행 중 상태가 끝날 때까지 기다립니다.
  3. 실행 ID와 탐지 상태가 표시된 요약을 촬영합니다.

콘솔은 지정된 흐름만 호출하며, 임의 OS 명령이나 외부 주소를 실행하지 않습니다.

화면에서 잡을 결과

판정탐지
세션생성
자료20건
수신확인

단계에는 제한된 모의 웹 세션 생성, 합성 지원 자료 조회, 내부 수신기로 전송이 차례로 표시됩니다.

“진단 입력 처리에서 제한된 모의 웹 세션이 만들어졌고, 지정 자료의 조회와 내부 수신 결과가 같은 실행으로 연결되었습니다.”
3

탐지와 증거 대조

콘솔의 단계 결과와 이벤트 로그에서 관측된 증거를 같은 실행 단위로 확인합니다.

보안 관찰

시나리오 단계

  1. 세션 생성
  2. 지정 합성 자료 조회
  3. 내부 수신 결과
  4. 탐지 상태

각 단계가 완료된 순서와 실행 ID를 보여 줍니다.

이벤트 로그

  1. 보안 이벤트 탭에서 비정상 진단 입력, 세션 생성, 자료 조회, 전송 결과를 확인합니다.
  2. 실행 로그 탭에서 처리 순서를 확인합니다.
  3. 로그가 타이핑처럼 순차 표시된 뒤 건수 20건과 SHA-256 수신 결과를 촬영합니다.
콘솔 실행은 콘솔의 실행 이력과 상세 타임라인에 남습니다. evidence/runs/ 파일은 별도로 명령행 검증 도구를 실행했을 때 생성되는 보관 증거입니다. 토큰이 포함될 수 있는 원시 파일은 촬영 화면에서 열지 않습니다.
4

운영자 대응과 세션 폐기

탐지 후 운영자가 콘솔에서 대응을 실행해 해당 실행을 차단합니다.

수동 대응

콘솔 조작

  1. Before 실행이 선택된 상태에서 대응 실행을 선택합니다.
  2. 터미널이 04 · 운영자 대응 세션으로 전환된 뒤 완료될 때까지 기다립니다.
  3. 실행 상태와 이벤트 로그가 갱신되는 장면을 촬영합니다. 이어지는 After 단계에서는 다시 새 터미널 세션이 열립니다.

기대 상태

실행대응 완료
경보차단
세션폐기
보호 안내등록

대응 뒤 이전 실행으로 새 세션 생성, 자료 조회, 전송은 거부됩니다.

“탐지는 자동으로 기록됐고, 세션 폐기와 보호 안내 등록은 운영자 대응으로 완료됐습니다.”
5

After 차단 검증

동일한 비정상 흐름이 통제에서 차단되고 정상 진단이 유지되는지 확인합니다.

개선 확인

콘솔 조작

  1. 방어자 단계 중 터미널이 05 · After 차단 검증 세션으로 새로 전환됩니다.
  2. 새 터미널 화면에서 차단 결과와 후속 단계 상태를 확인합니다.
  3. 필요하면 다시 정상 진단을 실행해 정상 업무가 유지됨을 보여 줍니다.

기대 결과

입력차단
세션생성 없음
수신없음
후속 단계미실행

After는 Before와 별도 실행 ID로 생성됩니다. 자료 조회·전송은 성공이 아니라 선행 차단에 따른 미실행으로 표시합니다.

6

회원 보호 안내 확인

대응으로 등록된 안내가 영향 회원에게만 보이는지 확인합니다.

회원 포털

영향 회원

  1. haeon01로 마이페이지에 로그인합니다.
  2. 추가 확인 안내와 발생 시각을 촬영합니다.
  3. 확인 버튼을 눌러 확인 완료 상태가 남는지 보여 줍니다.

비교 회원

  1. haeon02로 로그인합니다.
  2. 동일 안내가 노출되지 않는지 확인합니다.
  3. 안내 확인은 읽음 기록이며 카드 사용 중지나 사고 종결을 의미하지 않는다고 설명합니다.

촬영 종료와 다음 통합 작업

필수 장면은 가맹점 정상 진단, 콘솔 Before 탐지와 20건 수신, 대응 완료, After 차단·미실행, 회원 보호 안내입니다.

bash tools/haeon-diagnostic-lab.sh reset
bash tools/network-port-security-check.sh

초기화는 시나리오 실행·세션·보호 안내만 정리하며, 정상 결제 데이터와 보관된 증거는 유지합니다. 콘솔 이력은 남을 수 있으므로 다음 촬영에는 새 실행을 선택합니다. 북웨이브·PG 연동은 이 촬영과 별도 브랜치·worktree에서 통합합니다.

이 프로젝트는 무슨 게임인가?

인터넷 쇼핑몰에서 결제가 카드사까지 안전하게 흐르는 길을 만들고, 길에서 생길 수 있는 문제를 일부러 재현한 뒤 고치는 프로젝트입니다.

WORLD 01북웨이브

상품을 고르고 주문을 생성하는 온라인 서점

WORLD 02모의 PG

결제 요청을 카드사에 전달하는 중간 우체국

WORLD 03해온카드

회원·가맹점 결제와 승인 서비스를 제공

01 · 프로젝트 개요

무엇을 왜 만들었나?

가짜 온라인 서점과 카드사를 연결해 결제 보안 문제를 안전하게 연습합니다.

“실제 금융망 없이, 재현 가능한 실습실을 만들었습니다.”
02 · 진행과정

어떻게 진행했나?

아키텍처를 먼저 정하고, WBS·OPR로 역할과 순서를 나눈 뒤 코드를 연결했습니다.

“2명이 책임을 나누되 계약과 테스트는 함께 확인했습니다.”
03 · 현재까지

지금 무엇이 보이나?

북웨이브 화면과 해온카드 승인 API 뼈대, DB fixture, 정상 결제 확인 절차가 있습니다.

“설계는 고정했고, 정상 흐름에서 공격·개선 비교로 넘어가는 중입니다.”
04 · 앞으로

무엇을 더 증명하나?

두 요청을 동시에 보내 Before를 재현하고, 잠금 적용 후 After와 로그를 비교합니다.

“화면이 아니라 응답·DB·로그가 같은 결론인지 확인하겠습니다.”

🔎증거 폴더응답·로그·숫자를 남긴다

발표에서 이렇게 설명하세요

  1. 북웨이브가 “이 카드로 이 금액을 결제해도 될까요?”라고 PG에 보냅니다.
  2. PG는 요청을 해온카드에 전달하고, 카드가 준 답을 그대로 북웨이브에 돌려줍니다.
  3. 해온카드는 카드의 남은 한도를 보고 승인 또는 거절을 결정합니다.
  4. 카드 DB는 한도·승인 요청·확정 거래·감사 기록을 남깁니다.
  5. 우리는 같은 상황을 Before(문제가 있는 길)와 After(잠금으로 고친 길)로 비교합니다.

SPEAK LIKE A HUMAN

어려운 단어를 말로 바꾸기

카드에서 단어를 누르면 발표 때 쓸 수 있는 쉬운 문장이 열립니다.

두 사람이 같은 순간 같은 장부를 보고 결정해서, 한도 계산이 꼬이는 현상입니다.
여러 기록을 한 묶음으로 처리하는 약속입니다. 전부 성공하거나 전부 취소합니다.
한도 한 줄을 잠깐 맡아 두고, 한 사람씩 읽고 고치게 하는 방법입니다.
같은 결제 요청을 다시 보내도 돈과 거래가 두 번 생기지 않는 성질입니다.
북웨이브·PG·카드의 장부를 나란히 놓고 숫자와 상태가 같은지 비교하는 일입니다.
한 결제의 이름표입니다. 서비스가 달라도 같은 요청을 따라갈 수 있습니다.
실제 사람이나 카드가 아닌, 실습을 위해 만든 가짜 데이터입니다.
“그럴 것 같다”가 아니라 응답·DB·로그로 결과를 다시 확인할 수 있는 정도입니다.
한 서비스가 다른 서비스의 말을 무조건 믿으면 안 되는 경계입니다. 받은 값과 원본을 확인해야 합니다.
Windows 안에서 Linux 명령과 Docker 실습을 할 수 있게 해 주는 작업 공간입니다.
